# Установка Taskmanag на собственный сервер

## Что устанавливается

Это согласованная к передаче демонстрационная версия: статический HTML-интерфейс на русском языке. Сервер раздаёт один файл; приложения на сервере, API и базы данных пока нет.

**Установка на общий сервер не создаёт совместное рабочее пространство.** Поручения, сотрудники и оценки сохраняются отдельно в `localStorage` каждого браузера. Пользователи не увидят изменения друг друга. Авторизация, права доступа, серверное хранение и аудит должны быть реализованы в следующей версии до использования портала как общей системы поручений.

## 1. Получить проект

```sh
git clone https://github.com/OsWaX/taskmanag.git
cd taskmanag
```

Для закрытого репозитория используйте штатную авторизацию вашей IT-команды в GitHub.

Готовый файл `demo.html` уже включён в репозиторий. Для его размещения Node.js, npm, Python и установка зависимостей не нужны — достаточно существующего веб-сервера (Nginx, Apache, IIS или другого сервера статических файлов).

## 2. Разместить статический файл

Скопируйте `demo.html` в отдельный каталог сайта под именем `index.html`. Не используйте весь Git-репозиторий как публичный каталог веб-сервера.

Пример для Linux, выполняемый администратором сервера из каталога проекта:

```sh
sudo install -d -m 0755 /var/www/taskmanag
sudo install -m 0644 demo.html /var/www/taskmanag/index.html
```

Далее настройте существующий виртуальный хост на каталог `/var/www/taskmanag` и стартовый файл `index.html`. Для Nginx в существующем блоке `server` соответствующей площадки:

```nginx
root /var/www/taskmanag;
index index.html;

location / {
    try_files $uri $uri/ =404;
}
```

Домен, HTTPS, доступ из внутренней сети и параметры виртуального хоста настраиваются по стандартам вашей инфраструктуры. После изменения конфигурации проверьте её штатными средствами сервера; для Nginx — `sudo nginx -t`, затем перезагрузите конфигурацию.

Этот фрагмент — пример интеграции с вашим существующим Nginx, а не проверенная конфигурация вашего сервера. В среде разработки проверена раздача того же HTML через HTTP и работа интерфейса в Chromium.

## 3. Проверить установку

1. Откройте адрес сайта: должен появиться раздел «Обзор» с пометкой «ДЕМО».
2. Создайте тестового сотрудника и поручение. Обновите страницу и убедитесь, что изменения сохранились в том же браузере.
3. Заполните чек-лист и отчёт, сохраните статус «На проверке», затем примите результат с датой выполнения и оценкой качества.
4. В разделе «Эффективность» выберите месяц срока поручения и проверьте KPI.
5. Скачайте отчёт CSV и резервную копию JSON; проверьте восстановление копии через «Настройки».
6. На другом браузере должны отображаться отдельные демонстрационные данные — это ожидаемое поведение этой версии.

## Сборка из исходников

Если IT-команда меняет исходники, потребуется Node.js 20 или новее:

```sh
npm run build
npm test
```

`npm install` для сборки не требуется: внешних зависимостей нет. После успешных проверок повторно скопируйте новый `demo.html` в каталог сайта как `index.html`.

Для локальной разработки доступен `npm start` (Python 3, порт 4173). Этот сервер предназначен для разработки; для размещения на собственном сервере используйте инфраструктуру статических сайтов вашей команды.

## Обновление и данные

- Перед обновлением пользователи могут скачать резервную копию JSON в «Настройках».
- Сохранённые данные привязаны к браузеру и origin сайта (протокол, домен, порт). При смене HTTP на HTTPS, домена или порта данные автоматически не переносятся: используйте экспорт и импорт JSON.
- Серверная резервная копия HTML не содержит пользовательских поручений. Они находятся в браузерах, пока не реализовано серверное хранение.
- Очистка данных браузера удаляет локальное рабочее пространство.
- Для демонстрации не требуются ключи API, SMTP, внешние сервисы или секреты.
